## 1. SYSTEM OVERVIEW

**What it does:** A personal knowledge vault where Claude reads raw articles and notes, writes structured wiki summaries, updates concept/domain pages, answers knowledge queries, and runs lint checks on the wiki.

**What triggers it:** User message in Claude Code CLI (interactive, manual, on-demand). No webhooks, no API endpoint, no scheduled jobs.

**What it outputs / actions taken:**
- Writes new Markdown files to `wiki/sources/`, `wiki/concepts/`, `wiki/domains/`, `wiki/synthesis/`
- Updates existing wiki pages in-place (revises Overview and Key Claims sections)
- Updates `index.md` (full catalog) after every ingest
- Appends entries to `log.md` (append-only activity log)
- Reads external URLs via WebFetch (domain-restricted; see Data Layer)

## 2. MODEL SETUP

**Approximate system prompt length:**

**Dynamic values near the top that break prompt caching:**
- `currentDate` (today's date: `2026-05-26`) is injected by the Claude Code harness into every context window via `<system-reminder>` — not in `CLAUDE.md` itself, but rendered before it in the actual context. This fires on every call and breaks prefix caching.
- `userEmail` (`vladimir.shchedrin@manychat.com`) is injected the same way.
- `gitStatus` (branch name, recent commits) is injected at session start — changes every commit.
- The `skills-lock.json` computedHash and list of available skills is injected per session.

## 4. AGENT ARCHITECTURE

**Architecture type:** Single LLM call per conversation turn. No workflow engine, no predefined step graph, no multi-agent orchestration. The three workflows (Ingest / Query / Lint) are numbered steps in `CLAUDE.md` prose — Claude follows them as instructions, not as enforced code.

**Full tool inventory:**
| Tool | Access type | Reversible? |
|------|-------------|-------------|
| Read | Read-only | N/A |
| Write | Write (create/overwrite files) | Soft (git-tracked) |
| Edit | Write (partial file edit) | Soft (git-tracked) |
| Bash | Read+Write+Execute | Depends on command |
| WebFetch | External read (domain-restricted) | N/A |
| Agent | Spawns subagents | Depends on subagent |
| WebSearch | External read | N/A |

**Write-action tools with irreversibility notes:**
- `Write` and `Edit` overwrite files on local filesystem. Soft-reversible via git (`git reset` or `git checkout`). The repo is tracked (see `gitStatus`).
- `CLAUDE.md` convention: "Never modify files under `raw/`" — this is a prompt rule, not a code constraint. Bash could still overwrite raw files if instructed.
- No hard-delete tools; `rm` via Bash is possible and would be irreversible without git.

**Human-in-the-loop steps:**
- Ingest workflow step 2 is explicitly: "Discuss key takeaways with Vova before writing." This is a mandated conversational pause before any files are created — enforced by prompt, not code.
- No other gates. Query and Lint workflows have no explicit pause steps.

**Scheduled / automated runs:** NOT FOUND. All runs are manual.

## 6. KNOWN ISSUES

**Documented incidents:**
1. **Personal data over-ingestion (2026-05-07):** `raw/notes/` was ingested (creating `wiki/self/`, `wiki/people/`, and personal domain pages), then entirely deleted in a cleanup operation. Root cause: no scope filter on ingest — the ingest workflow processes whatever raw files it's pointed at.
2. **Duplicate log entry (2026-05-07):** The 57-article batch ingest (MDN Security, OWASP, web.dev Performance) was logged twice in `log.md` — once as "57 articles batch (added to raw/)" and once as "57 articles ingested (source summaries created)". Log append-only convention means this can't be corrected.

**Structural gaps:**
- `wiki/synthesis/` is empty. The synthesis workflow is defined in `CLAUDE.md` and the directory exists, but no synthesis pages have ever been created. The query workflow offers to create a synthesis page ("if the answer is non-trivial, offer to file it") — this offer has never been accepted.
- `index.md` is manually maintained by Claude. There is no validation that it accurately reflects actual files in `wiki/`. A page can be created without an index entry, and vice versa.
- WebFetch domain allowlist contains only `backstage.spotify.com`. Any ingest workflow that needs to fetch a live URL (e.g., to re-fetch an article) will either fail or prompt the user unless the article is already saved in `raw/articles/`.

**Parts of the system the operator avoids:**
- No evidence of avoidance patterns. The vault is young (created 2026-05-04).

**Last unexpected behavior:**
- Personal notes ingested into wiki (2026-05-07), discovered when reviewing the vault contents, corrected via manual cleanup conversation. Detection method: user reviewed what was created.
