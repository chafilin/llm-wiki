## Summary
Codecov's argument for focusing enforcement on patch coverage (coverage of new code in a PR) over project coverage (entire codebase). "A developer should test their own code versus test all of the code."

## Key takeaways
- Project coverage: comprehensive but pursuing 100% is unrealistic and burdensome
- Patch coverage: coverage of lines changed in a specific PR — actionable within developer workflow
- Enforcing patch coverage catches bugs before they merge, without demanding 100% coverage of legacy code
- Codecov auto-measures and reports both in CI
